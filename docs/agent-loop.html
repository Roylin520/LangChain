LangChain v1 · Day 1 Lab

Agent 迴圈

Agent 不是更聰明的模型，是一個「呼叫模型 → 執行工具 → 把結果餵回模型」的迴圈——而迴圈要跑幾輪，由模型自己決定。

範例
src/01_basic_agent.py
版本
langchain 1.3.18
模型
ollama:nemotron-3-nano:4b

01先把定義釘死

Agent＝模型與工具之間的一個受控迴圈。程式負責執行工具、維護對話；模型負責決定「還要不要再呼叫工具」。

這是 agent 跟一般 LLM 呼叫唯一的本質差別。普通呼叫是「輸入 → 模型 → 輸出」，一次結束；agent 讓模型在回話時可以說「我還不能回答，先幫我執行這個函式」，程式跑完把結果貼回對話，再問一次——直到模型不再要求工具。

教這一段時，有兩個誤解一定要先拆掉，否則後面談權限與安全會全部歪掉。

  • 誤

    「Agent 是更聰明的模型。」

    模型完全沒變。同一個 nemotron-3-nano:4b，換掉外面那圈控制流程就從聊天機器人變成 agent。變的是流程，不是模型。

  • 誤

    「Agent 會自己執行程式。」

    模型只能輸出一段 JSON，說明它想呼叫哪個函式、帶什麼參數。真正執行 Python 的是 LangChain 的程式碼，在你的機器上、用你的權限。模型從頭到尾沒有執行能力。

02create_agent 造出來的是一張圖

這行 create_agent(...) 回傳的不是一個 Agent 物件，而是一張編譯好的 LangGraph 狀態圖（CompiledStateGraph）。把它的節點與邊印出來，就是下面這張圖——不是示意圖，是實際結構。

迴圈的結束條件只有一行

分岔判斷寫在 langchain/agents/factory.py。原始碼的註解自己講得很白——這就是 agent 迴圈的經典結束條件，沒有別的魔法：

factory.py:1952-1955# 3. If the model hasn't called any tools, exit the loop
# this is the classic exit condition for an agent loop
if len(last_ai_message.tool_calls) == 0:
    return end_destination

換句話說：每一輪模型回話後，程式只檢查一件事——這則 AI 訊息裡有沒有 tool_calls。有就去 tools 節點，沒有就結束。

03真的跑一次，裡面長什麼樣

把 agent.invoke() 回傳的完整訊息序列印出來。問題是「請計算 18 * (23 + 7)，並用一句話說明。」，最後產生 4 則訊息：

[0]
HumanMessage

請計算 18 * (23 + 7)，並用一句話說明。

[1]
AIMessage

content = ''　　← 空字串

[{"name": "safe_calculate",
  "args": {"expression": "18 * (23 + 7)"},
  "id": 6443b657-30ee-439b-be9e-494bdeaef0b2,
  "type": "tool_call"}]
模型這一輪一個字都沒說。它整個回應就是「我要呼叫這個工具」。這證明模型的輸出不只是文字——content 與 tool_calls 是兩個並存的欄位。
[2]
ToolMessage

540.0

tool_call_id = 6443b657-30ee-439b-be9e-494bdeaef0b2
name = "safe_calculate"
這則的 tool_call_id 跟上一則的 id 一模一樣。當模型一次要求呼叫三個工具時，就是靠這個 id 把每個結果對回它自己的請求。
[3]
AIMessage

18 × (23 + 7) = 540。計算過程是先把括號內的 23 + 7 算成 30，然後 18 × 30 等於 540。

這一輪模型看到的對話裡已經多了「工具回傳 540.0」，它才據此寫出答案。沒有 tool_calls → 迴圈結束。

對照第 02 節那張圖，實際走過的路徑是：

__start__→ model→ tools→ model→ __end__

model 節點被執行了兩次，也就是對模型發了兩次請求。這點在算成本時很重要：一次 agent 呼叫不等於一次模型呼叫。

另外，整個 state 印出來只有 ['messages'] 一個 key——因為這個範例沒有用到 state_schema、response_format 或 checkpointer。

04模型怎麼「知道」有這個工具

程式裡只寫了 tools=[safe_calculate]，傳進去一個普通 Python 函式。LangChain 會把它轉成 JSON Schema 送給模型。左邊是你寫的，右邊是模型真正收到的：

你寫的 Python

def safe_calculate(expression: str) -> str:
    """Calculate a simple arithmetic
    expression, such as '3 * (5 + 2)'."""
    ...

模型收到的 schema

{
  "name": "safe_calculate",
  "description": "Calculate a simple
     arithmetic expression, such as
     '3 * (5 + 2)'.",
  "parameters": {
    "properties": {
      "expression": {"type": "string"}},
    "required": ["expression"],
    "type": "object"}}
name← 函式名稱
description← docstring，逐字照抄
parameters← 型別註記 expression: str

所以 docstring 不是註解，是給模型看的規格書。docstring 寫得爛，模型就會挑錯工具或給錯參數格式。這裡的 docstring 特地附上 '3 * (5 + 2)' 這個範例，就是在示範該傳什麼格式；型別註記漏寫，schema 裡的 type 也會跟著失準。

05程式逐段

L19、L21

load_dotenv() ＋ os.getenv("MODEL_NAME", ...)

把 .env 讀進環境變數，金鑰不落在程式碼裡。MODEL_NAME 的格式是 provider:model，LangChain 會依前綴去找對應的 provider 套件——所以 ollama: 開頭就必須裝 langchain-ollama，否則初始化就失敗。

L23–L47

AST 白名單：整份範例的安全重點

工具參數是模型生成的字串，等同外部不可信輸入。若寫成 eval(expression)，送進 __import__('os').system(...) 就直接執行了。這裡改用 ast.parse 解成語法樹，只放行白名單上的六種二元運算與兩種一元運算，遇到函式呼叫、變數、屬性存取一律 raise ValueError。

L55–L56

例外轉成字串回傳，而不是往上拋

回傳 f"計算失敗：{exc}"，這個字串會變成 ToolMessage 送回模型，讓模型有機會自己修正參數重試。工具失敗不該中斷 agent 迴圈——這是刻意的設計，不是偷懶。

L62–L65

system_prompt：「遇到數學計算請用 safe_calculate，不要心算」

這是建議，不是強制。模型仍可以選擇不呼叫工具直接心算。要示範這點，把這兩句拿掉再跑一次，小模型很可能就自己算了——而且可能算錯。

L69–L72

agent.invoke({"messages": [...]})

輸入與輸出的形狀相同，都是 {"messages": [...]}。result["messages"][-1] 取最後一則，就是第 03 節的 [3]。

06這堂課只用了三個參數

create_agent 在 v1.3.18 共有 15 個參數。這份 Lab 用了三個，其餘對應後續課程主題：

參數本 Lab它控制什麼
model已用provider:model 字串，決定 model 節點打給誰
tools已用有沒有 tools 節點。傳空陣列時圖裡根本不會建立這個節點
system_prompt已用每次呼叫模型時置頂的指示
middleware未用在 model／tools 前後插入 hook（before_model、after_model…）
response_format未用結構化輸出：用 Pydantic 模型驗證回應
checkpointer未用記憶：跨次呼叫保留 messages
store未用長期記憶，跨 thread 共用
interrupt_before未用human-in-the-loop：執行工具前先暫停等人同意
state_schema未用在 messages 之外自訂 state 欄位
context_schema未用執行期傳入、不進對話的上下文

其餘五個：cache、name、debug、interrupt_after、transformers。

07課堂上值得現場跑的三個實驗

  1. 把 tools=[] 清空

    模型只能心算，而且圖裡連 tools 節點都不會被建立——LangChain 是有工具才 add_node。用 agent.get_graph().nodes 印出來給學員看。

    預期：節點剩 ['__start__', 'model', '__end__']

  2. 改問「今天天氣如何」

    模型判斷這題不需要計算工具，直接回答。示範「條件邊」真的是條件——不是每次都會走 tools。

    預期：只有 2 則訊息，路徑 start → model → end

  3. 問一個需要兩步的題目

    例如「算 3*4，再把結果乘以 2」。觀察迴圈跑幾輪、模型是一次要求兩個 tool_call 還是分兩輪。不同模型行為不同，這正是可以討論的地方。

    預期：訊息數 > 4，model 節點執行 3 次以上

08學員大概會撞到的三個錯誤

ModuleNotFoundError: No module named 'dotenv'

虛擬環境是空的。venv 建好不等於裝好套件。先 pip install -r requirements.txt。注意 requirements 目前沒有列 langchain-ollama，用 Ollama 的話要另外補裝。

UnicodeEncodeError: 'cp950' codec can't encode character '\u202f'

Windows 主控台編碼問題，不是 LangChain 的錯。Agent 其實已經跑完拿到答案，是最後 print() 才炸掉——模型回答裡有 U+202F（窄不斷行空格），cp950 編不出來。解法：腳本開頭加 sys.stdout.reconfigure(encoding="utf-8")，或設環境變數 PYTHONUTF8=1。

httpx.ConnectError: [WinError 10061] 無法連線，因為目標電腦拒絕連線

Ollama 服務沒在跑。Windows 上 Ollama 會自己停掉。執行 ollama list 就會把它重新叫起來。用雲端 provider 的學員不會遇到，用本機模型的一定要先提醒。
